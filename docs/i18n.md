# Multi-Language Support (i18n) Implementation

## Overview

The Expense Manager now supports multi-language (internationalization) with built-in support for:
- **English** (en)
- **Spanish** (es)
- **French** (fr)
- **Urdu** (ur)
- **German** (de)

The implementation follows Yii2's i18n best practices using PHP message source files.

## Architecture

### Directory Structure

```
project/
├── messages/                    # Translation files
│   ├── en/
│   │   └── app.php            # English translations
│   ├── es/
│   │   └── app.php            # Spanish translations
│   ├── fr/
│   │   └── app.php            # French translations
│   ├── ur/
│   │   └── app.php            # Urdu translations
│   └── de/
│       └── app.php            # German translations
├── components/
│   └── LanguageSelector.php   # Bootstrap component for language selection
├── widgets/
│   └── LanguageSwitcher.php   # UI widget for language switching
└── config/
    ├── params.php              # Supported languages configuration
    └── web.php                 # i18n component configuration
```

### Configuration Files

#### `config/params.php`

Defines the supported languages:

```php
'supportedLanguages' => [
    'en' => 'English',
    'es' => 'Español',
    'fr' => 'Français',
    'ur' => 'اردو',
    'de' => 'Deutsch',
],
'defaultLanguage' => 'en',
```

#### `config/web.php`

i18n component configuration:

```php
'i18n' => [
    'translations' => [
        'app*' => [
            'class' => 'yii\i18n\PhpMessageSource',
            'basePath' => '@app/messages',
            'sourceLanguage' => 'en',
        ],
    ],
],
```

Bootstrap configuration:

```php
'bootstrap' => [
    // ...
    [
        'class' => 'app\components\LanguageSelector',
        'supportedLanguages' => ['en', 'es', 'fr', 'ur', 'de'],
    ],
    // ...
],
```

## Language Priority

The LanguageSelector component determines the application language based on this priority:

1. **Authenticated users**: Language preference from `settings.language` table field
2. **Guests**: Browser's preferred language (using Accept-Language header)
3. **Default**: Application's default language (en)

## Using Translations

### In Views

Use the `Yii::t()` function to translate strings:

```php
<?= Yii::t('app', 'Login') ?>
<?= Yii::t('app', 'Dashboard') ?>
<?= Yii::t('app', 'Add Expense') ?>
```

### In Controllers

Translate messages in controller actions:

```php
Yii::$app->session->setFlash('success', Yii::t('app', 'Operation completed successfully.'));
```

### In Models

Add translations in model methods:

```php
public function attributeLabels(): array
{
    return [
        'name' => Yii::t('app', 'Name'),
        'email' => Yii::t('app', 'Email'),
    ];
}
```

## Features

### 1. Language Switcher Widget

Display a dropdown language selector in the navigation bar:

```php
<?= LanguageSwitcher::widget(['style' => 'dropdown']) ?>
```

**Styles available:**
- `'dropdown'` - Dropdown menu style (default)
- `'inline'` - Inline button group style

**Options:**
```php
<?= LanguageSwitcher::widget([
    'style' => 'dropdown',
    'containerClass' => 'custom-class',
]) ?>
```

### 2. Language Change Action

Users can change their language preference:

**For authenticated users:**
- Changes are saved to the `settings.language` database field
- Persists across sessions

**For guests:**
- Language is stored in a session/cookie
- Only valid for the current session

**URL:** `/site/change-language?lang=es`

### 3. Automatic Language Selection

#### For Authenticated Users

The `LanguageSelector` bootstrap component automatically:
1. Reads the user's language preference from `settings.language`
2. Sets `Yii::$app->language` accordingly
3. Falls back to the default language if not set

#### For Guests

1. Detects browser's preferred language using Accept-Language header
2. Validates against supported languages list
3. Falls back to default language if not supported

## Database Migration

The language support requires a migration to add the `language` column to the `settings` table:

```php
// Migration: m260608_000000_add_language_to_settings.php
$this->addColumn('{{%settings}}', 'language', $this->string(10)->defaultValue('en')->after('user_id'));
```

### Running the Migration

```bash
php yii migrate
```

## Adding New Languages

To add support for a new language:

1. **Create message file:**
   ```
   messages/{language_code}/app.php
   ```

2. **Add translations to the file:**
   ```php
   return [
       'Login' => 'Translated Text',
       'Dashboard' => 'Translated Text',
       // ... more translations
   ];
   ```

3. **Update configuration in `config/params.php`:**
   ```php
   'supportedLanguages' => [
       'en' => 'English',
       'pt' => 'Português',  // Add new language
   ],
   ```

4. **Update bootstrap configuration in `config/web.php`:**
   ```php
   'supportedLanguages' => ['en', 'es', 'fr', 'ur', 'de', 'pt'],
   ```

## Adding New Translations

To translate a new string in your code:

1. **In your code, use:**
   ```php
   Yii::t('app', 'Your new string')
   ```

2. **Add translation in each language file:**
   - `messages/en/app.php`
   - `messages/es/app.php`
   - `messages/fr/app.php`
   - `messages/ur/app.php`
   - `messages/de/app.php`

   ```php
   'Your new string' => 'Translated text for this language',
   ```

## Translation Categories

All translations in this application use the `'app'` category. This means:

```php
Yii::t('app', 'message_key')
```

Messages are stored in: `messages/{language}/app.php`

## Best Practices

### 1. Always Use Translation Keys

```php
// ✓ Good
<?= Yii::t('app', 'Login') ?>

// ✗ Bad
<?= 'Login' ?>
```

### 2. Organize Translations Logically

In the message files, group related translations with comments:

```php
return [
    // ========== Navigation & Menu ==========
    'Login' => 'Login',
    'Dashboard' => 'Dashboard',
    
    // ========== Forms ==========
    'Email' => 'Email',
    'Password' => 'Password',
];
```

### 3. Use Meaningful Keys

```php
// ✓ Good
'Please fill out all required fields.' => 'Please fill out all required fields.',

// ✗ Bad
'msg_001' => 'Please fill out all required fields.',
```

### 4. Avoid Concatenation

```php
// ✓ Good
Yii::t('app', 'Welcome back!')

// ✗ Bad
Yii::t('app', 'Welcome') . ' ' . Yii::t('app', 'back!')
```

### 5. Parameterized Messages

For dynamic content, use parameters:

```php
// In app.php
'Hello {name}' => 'Hello {name}',

// In code
Yii::t('app', 'Hello {name}', ['{name}' => $userName])
```

## Debugging i18n Issues

### Check Current Language

```php
echo Yii::$app->language;  // Returns current language code
```

### Verify Translation Exists

```php
// Will return the key if translation not found
echo Yii::t('app', 'Non-existent key');  // Outputs: Non-existent key
```

### Check Message Files

Ensure the file path is correct:
- File location: `@app/messages/{language}/app.php`
- Returns as: `messages/{language}/app.php`

### Enable Debug Mode

In development, missing translations appear in the Debug Bar:
- Messages showing the original key indicate missing translations
- Check logs for i18n-related errors

## Performance Considerations

- Message files are cached by Yii after first load
- Language switching doesn't require page reload for authenticated users
- Browser cache respects language preference for guests

## Internationalization Events

The application emits no specific events for language changes, but you can:

1. **Hook into the `actionChangeLanguage` method** to add custom logic
2. **Listen to user settings updates** if extended with events

## Formatter Settings by Language

The `LanguageSelector` also handles locale-specific formatting:

- **Currency**: From user settings or default (PKR)
- **Date Format**: From user settings or default (d/m/Y)
- **Decimal Separator**: From user settings or default (.)
- **Thousand Separator**: From user settings or default (,)

## Troubleshooting

### Translations Not Appearing

1. Check message file exists: `messages/{language}/app.php`
2. Verify key matches exactly (case-sensitive)
3. Clear application cache: `@app/runtime/cache/`
4. Enable debug mode to see errors

### Language Not Changing

1. For authenticated users: Check `settings.language` field value
2. For guests: Verify browser's Accept-Language header
3. Check if language is in `supportedLanguages` configuration
4. Ensure `site/change-language` action is accessible

### Special Characters Not Displaying

1. Ensure all message files are saved as UTF-8
2. Verify `<?php` header declares UTF-8 charset
3. Check web.php: `'charset' => 'UTF-8'`
